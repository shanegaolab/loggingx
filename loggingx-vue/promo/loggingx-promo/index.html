一行日志经过的五个环节，各管一种故障

  1. app.log* 日志文件

    Agent 不在时，应用照常往文件里写；停机期间轮转出的新文件从头读。

    管：Agent 停机、升级
  2. 数据目录 读取位置

    日志确认存进缓冲后，读取位置才往前走；重启后从这里接着读。

    管：崩溃、断电重启
  3. 1 GiB / 每台主机 磁盘缓冲

    连不上 LoggingX 时先存在本机；满了就暂停读取，不丢弃任何一行。

    管：断网、LoggingX 宕机
  4. 退避最长 60 秒 失败重试

    网络错误、超时、服务端 5xx 都会一直重试，直到成功。

    管：网络抖动、服务重启
  5. 服务端 · 30 分钟内 按批次去重

    日志已入库、只是回复丢了时，重发的同一批会被认出来，不存两遍。

    管：重试造成的重复

常见问题

上线前大家常问的

需要改业务代码吗？

不需要。Agent 直接读取服务器上的日志文件和容器输出，Java、Python 的异常堆栈会自动合并成一条。已有的采集器（如 Fluent Bit）也可以直接把日志上报到 LoggingX 的 HTTP 接口，或者走 Kafka。

支持哪些服务器环境？

Linux（systemd）、Windows（计划任务）、Docker 和 Kubernetes（DaemonSet）都有现成的安装方式。内网环境可以把安装包放到内网镜像，Agent 从内网下载安装。

日志能存多久？

每个日志库单独设置保留天数。开启归档后，更早的日志按天压缩存进 MinIO、阿里云 OSS、腾讯云 COS 或 AWS S3，需要时下载，或一键恢复回日志库查询。

AI 用的是哪家模型？代码会发到哪里？

支持 DeepSeek、OpenAI 和 Anthropic Claude，在页面上选择即可，也可以指向公司内部的模型网关。分析用到的日志和代码片段只发给你选择的模型，代码仓库的访问令牌加密保存。

不同团队能分开管理吗？

可以。在角色上分配可访问的日志库，各团队只看到自己的日志、主机、告警和 AI 诊断；菜单和操作权限也按角色配置。
